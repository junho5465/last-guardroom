# 최후의 경비실 · Last Guardroom

마지막 아파트 101동을 지키는 모바일 세로형 랜덤 소환·합성 디펜스. TypeScript + Phaser 3 + Vite.

0.2: 전용 로비 일러스트, 생존자·적·보스 16종 전투 아트, 모바일 UI를 개편했습니다. 디자인 변경은 [DESIGN.md](DESIGN.md)를 참고하세요.

## 실행

- 웹 플레이: https://junho5465.github.io/last-guardroom/
- Node.js 24 이상에서 `npm install` 후 `npm run dev` → http://localhost:5173
- 테스트: `npm test` / 배포 빌드: `npm run build`
- 앱인토스 번들: `npm run toss:build`

## 조작

시작 시 각 층에 생존자 1명씩 배치됩니다. 무료 소환 2회와 650골드로 전선을 만드세요. 같은 종류·같은 별 2명을 모아 한 명을 선택한 뒤 합성합니다. 경비원·소방관·전기기사는 3성부터 진화합니다. 선택 후 빈 방을 누르면 이동합니다. 전원 강화, 비상 포격, 5웨이브마다 나오는 강화 선택으로 20웨이브를 막으세요. 로비로 나가거나 새로고침해도 저장된 경비를 이어갈 수 있습니다.

## 구현

- 4층·12슬롯, 적 이동과 자동 공격·투사체·지속 피해·타격 효과
- 생존자 8종 / 적 6종 / 보스 2종 / 일반 20웨이브 / 클리어 후 무한 모드
- 랜덤 소환, 5성까지 합성, 주요 3종 각각 3방향 진화, 층 이동
- 실제 효과를 적용하는 강화 20종 / 랜덤 사건 6종
- 연구 6종·각 10레벨 상한, 연구 포인트와 최고 기록
- 선택형 모의 광고: 부활 1회, 임시 영웅 2회, 보스 보상 1회, 재추첨 2회, 긴급 지원 1회
- 영수증·횟수 검증, 정산 중복 방지, 저장 복원, 정지·재개, 1배/2배 속도
- 320px부터 모바일 터치 지원, 효과음과 타격 연출 설정

## 앱인토스 준비

공식 SDK 3.0.5와 apps-in-toss.config.ts를 포함합니다. appName의 임시값은 last-guardroom이며 콘솔에 등록하는 이름과 일치시켜야 합니다. 공식 가이드: https://developers-apps-in-toss.toss.im/ai-vibe-coding/tutorials/webview.md

콘솔 등록, 실기기 검증, 심사 요청은 아직 수행하지 않았습니다. 앱 정보·아이콘·등급·출시 자료를 준비한 뒤 토스앱에서 최종 테스트가 필요합니다. 실제 광고·결제는 연결하지 않았습니다. Platform 인터페이스의 모의 구현을 공식 보상 완료 콜백 기반 구현으로 교체해야 합니다. OneStore는 모의 어댑터이며 APK/AAB는 생성하지 않습니다.

## 구조

- src/data.ts: 유닛·적·강화·연구 데이터
- src/engine.ts: 화면과 분리된 전투·보상 엔진
- src/scene.ts: 자체 제작 Phaser 도형 아트와 연출
- src/main.ts: 로비·연구소·선택 화면과 터치 UI
- src/storage.ts: 저장소 인터페이스와 localStorage 구현
- src/platform.ts: 플랫폼별 보상형 광고 인터페이스
- tests/: 무결성 회귀 및 광고 없는 전체 플레이 시뮬레이션

## 한계 및 다음 버전

첫 플레이 가능한 버전이며 상용 출시 검증이 끝난 제품은 아닙니다. 드래그 합성, 진화별 상세 스프라이트, 고급 보스 연출, 서버 저장·계정 동기화·변조 방지·랭킹은 미구현입니다. 저장 데이터는 해당 브라우저에만 보관되며 데이터 삭제 시 기록을 잃습니다. 소환은 별도 전체 화면 대신 전투 내 배치·알림·효과로 표시됩니다. 장기 밸런스와 저사양 실기기 성능은 추가 테스트가 필요합니다.

다음 버전: 실기기 QA → 튜토리얼 → 전용 스프라이트·보스 연출 → 서버 저장 → 플랫폼 광고 완료 콜백 연동.
